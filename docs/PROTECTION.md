# MetaMago 2.2.0 — Protection Edition (candidato)

Apri un PDF non cifrato e non firmato accettato dal modulo PDF. Salva o ripristina eventuali modifiche pendenti. Nella sezione Proteggi documento PDF scegli esplicitamente originale o ultima copia metadati verificata. Imposta password proprietario obbligatoria e, se vuoi riservatezza, una password di apertura distinta. Per questa versione sono ammessi 12–64 caratteri ASCII visibili senza spazi. Conferma le password; usa credenziali robuste e un gestore di password. Non sono memorizzate dall'app, incluse nei report o nel backup, né recuperabili. Il browser/gestore password può avere propri comportamenti. Non è garantita la cancellazione sicura della memoria.

Stampa completa, bassa risoluzione o vietata. Modifica: nessuna; sola organizzazione pagine; organizzazione + moduli; organizzazione + moduli + commenti; tutte. Copia di testo e immagini separata. Le autorizzazioni sono i livelli PDF standard di QPDF, non una garanzia contro modifiche, screenshot o estrazione in software che non applica i permessi. L'accessibilità non viene disabilitata. Senza password di apertura, chiunque può aprire e leggere il PDF. La password proprietario controlla l'accesso privilegiato nei lettori compatibili; le restrizioni non sono una firma digitale.

Dopo conferma, viene prodotto un nuovo file _protetto.pdf con cifratura AES-256 revisione 6 (AESv3), anche metadati cifrati per impostazione predefinita. Nessuna sovrascrittura dell'originale. Prima del download: verifica QPDF JSON per metodo, bit, revisione, permessi e pagine, verifica credenziali utente e proprietario, richiesta password se impostata, qpdf --check. Rifiuta warning/errori del motore. Nessun fallback non cifrato. L'app non rimuove protezioni né apre documenti già cifrati. Limiti input PDF invariati (20 MiB), output 32 MiB. Verifica sempre la copia nel lettore. Test rendering su fixture sintetiche, non equivalenza universale.

## Architettura
QPDF 12.2.0 / @arshad-shah/qpdf-wasm 0.1.0 incorporato in HTML a build time con licenze wrapper e dipendenze native. Emscripten JS e WASM sono dati incorporati, eseguiti in un Worker module temporaneo con filesystem virtuale. Nessun fetch dei binari durante la protezione. CSP conserva script hash e connect-src none, aggiunge wasm-unsafe-eval per compilazione WebAssembly (non JavaScript eval); worker-src blob già presente. Nessun tentativo di aggirare policy: se il Worker/WASM non può funzionare, non si produce alcuna copia. Il limite di 180 secondi interrompe il Worker, non garantisce limiti di RAM. Versione npm esatta; SHA256 WASM stampato in build. Il checksum integrity npm della nuova dipendenza deve essere fissato dopo il primo riscontro dal registro prima della promozione stabile.
